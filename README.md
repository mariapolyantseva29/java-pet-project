# Запуск всего микросервиса

1. Запустить redis images на порту 6379 (порт по умолчанию) из docker.
2. Запустить kafka image на порту 9092 (порт по умолчанию) из docker.
3. Запустить postgres:14.5 image на порту 5454 из docker. Это будет база данных для сервиса thought.
4. Перейти в директорию проекта thought. Прогнать команду mvn flyway:migrate. Она прогонит миграции и добавит нужные таблицы в базу данных для сервиса thought.
5. Запустить postgres:14.5 image на порту 5455 из docker. Это будет база данных для сервиса auth-service.
6. Перейти в директорию проекта auth-service. Прогнать команду mvn flyway:migrate. Она прогонит миграции и добавит нужные таблицы в базу данных для сервиса auth-service.
7. Запустить проект logging-service с помощью запуска main метода.
8. Запустить проект auth-service с помощью запуска main метода.
9. Запустить проект thought с помощью запуска main метода.
10. Запустить проект gateway с помощью запуска main метода.
11. Теперь можно получить доступ к сайту на url localhost:8080.


# Что делает проект

* Проект предоставляет интерфейс (поле) для того, чтобы описать ситуацию, которая вызвала негативные эмоции.
И так же две колонки: левая для описания мыслей, которые возникают в данной ситуации. Правая колонка, для описания более позитивных и реалистичных мыслей.
* Все описанные пользователем ситуации храняться в базе данных и пользователь может получить к ним доступ при переходе на страницу /situations.
* На главной странице есть возможность получить все завершенные ситуации при нажатии на таб DONE.
* На главной странице есть возможность получить все незаконченные ситуации при нажатии на таб EDITED. Незаконченными являются те ситуации, где либо нет ни одной мысли,
либо если не у всех мыслей с правого столбика есть мысли с левого столбика.


# Описание работы каждого сервиса

### gateway

* Сервис является единой точкой входа в приложение. Перед тем как перенаправить запрос, сервис проверяет такие вещи как:
  * Зарегистрирован ли пользователь, если нет то перенаправляет на страницу регистрации.
  * Если зарегистрирован, то проверяет не привысил ли человек количество запросов используя redis.
* Отвечает за хранение и отдачу пользователю html страниц.

### auth-service

* Отвечает за аутентификацию пользователя. Сервис содержит один endpoint /api/auth/login.
  * Если пользователя нет в базе, то сервис создает его в базе данных и выдает jwt токен по которому потом будет идентифицировать пользователя.
  * Если пользователь есть в базе, то пользователя выгружают из базы и создают jwt токен.

### thought

* Отвечает за хранение, обновление, создание и отдачу пользователям ситуаций.

### logging-service

* Является центральной точкой всех логов которые есть в приложении.
* Логи отправляются через kafka с сервисов thought и auth-service.
